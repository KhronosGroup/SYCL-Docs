[[sec:khr-launch]]
= sycl_khr_launch

This extension helps reduce the latency when submitting commands to a queue by
restructuring the queue submission APIs.
There are three main changes.
First, the APIs in this extension no longer support the [code]#handler#
parameter.
Instead, functionality related to the handler has been replaced by a properties
parameter, which provides the same features without needing to store information
in a temporary [code]#handler# object.
Second, the APIs in this extension no longer return an event for each command
submission.
This allows applications to elide creation of an event in cases where the
application doesn't need one.
In cases where the application does need an event for a particular submission,
it can request that an event be signaled for that particular submission.
Finally, the model for events has been changed, so that an event object no
longer has a 1:1 correspondence with a single command.
An event can now be created independent from any command, and then later
associated with a particular command submission.
This allows a single event object to be reused across many submissions.

== Dependencies

This extension depends on the following other KHR extensions:

* sycl_khr_properties

== Usage example

The example below rewrites the application from
<<subsec:example.sycl.application>> to demonstrate the usage of this extension.

[source,role=synopsis]
----
#include <iostream>
#include <sycl/sycl.hpp>
using namespace sycl; // (optional) avoids need for "sycl::" before SYCL names.

// Size of the matrices.
constexpr size_t N = 2000;
constexpr size_t M = 3000;

int main() {
  // Create a queue to work on.
  queue myQueue;

  // Create some 2D arrays of float for our matrices.
  float* a = malloc_shared<float>(N * M, myQueue);
  float* b = malloc_shared<float>(N * M, myQueue);
  float* c = malloc_shared<float>(N * M, myQueue);

  // Launch an asynchronous kernel to initialize a.
  khr::launch(myQueue, range<2> { N, M }, [=](id<2> index) {
    size_t i = index[0];
    size_t j = index[1];
    a[i * M + j] = i * 2 + j;
  });

  // Launch an asynchronous kernel to initialize b.
  khr::launch(myQueue, range<2> { N, M }, [=](id<2> index) {
    size_t i = index[0];
    size_t j = index[1];
    b[i * M + j] = i * 2014 + j * 42;
  });

  // Ensure that the two previous kernels complete before enqueueing more work.
  // This does not block the host, but enforces dependencies on the device.
  khr::enqueue_barrier(myQueue);

  // Launch an asynchronous kernel to compute matrix addition c = a + b.
  // Require that the scheduler create an event to track completion.
  range<2> local = { 2, 2 };
  range<2> global = { N, M };
  event e = khr::make_event(myQueue.get_context());
  khr::properties props{khr::property::signal_event{e}};
  khr::launch_grouped(myQueue, global, local, [=](nd_item<2> it) {
    size_t i = it.get_global_id(0);
    size_t j = it.get_global_id(1);
    size_t index = i * M + j;
    c[index] = a[index] + b[index];
  }, props);

  // Wait for all three kernels to complete before accessing the results.
  // This blocks the host until all previous kernels have completed.
  e.wait();

  std::cout << std::endl << "Result:" << std::endl;
  for (size_t i = 0; i < N; i++) {
    for (size_t j = 0; j < M; j++) {
      size_t index = i * M + j;
      // Compare the result to the analytic value.
      if (c[index] != i * (2 + 2014) + j * (1 + 42)) {
        std::cout << "Wrong value " << c[index] << " on element " << i << " "
                  << j << std::endl;
        exit(-1);
      }
    }
  }

  std::cout << "Good computation!" << std::endl;
  return 0;
}
----

== Event creation

=== Function to create an event

This extension adds the following function to create an event.

'''

.[apidef]#khr::make_event#
[source,role=synopsis,id=api:make_event]
----
namespace sycl::khr {

template <typename PropertyOrList = khr::empty_properties_t>
event make_event(const context& c, PropertyOrList props = {});

} // namespace sycl::khr
----

_Constraints:_

* [api]#khr::is_property_for_v<PropertyOrList, event># is [code]#true#, or
* [api]#khr::is_property_list_for_v<PropertyOrList, event># is [code]#true#.

_Returns:_ An event that is associated with context [code]#c#.
The event is in the "signaled" state.

_Remarks:_ An event _E_ created with [code]#khr::make_event# can be used as a
command dependency (e.g. via [api]#khr::enqueue_wait_event#,
[api]#khr::property::wait_event#, or [code]#handler::depends_on#) for a command
submitted to some queue _Q_.
It is not necessary for the context of _E_ to match the context of _Q_.

An event _E_ created with [code]#khr::make_event# can also be associated with a
command submitted to some queue _Q_ such that _E_ is signaled when the command
completes (e.g. via [api]#khr::enqueue_signal_event# or
[api]#khr::property::signal_event#).
In this case, the context of _E_ and _Q_ must match.

If an event _E_ is used as a command dependency for some command _C_, the
dependency is captured at the point when _C_ is submitted.
It is legal to reassociate the event _E_ to a new command (e.g. via
[api]#khr::enqueue_signal_event# or [api]#khr::property::signal_event#) even
before command _C_ completes.
Doing so does not change the dependency for command _C_.

If another host thread is blocked waiting for event _E_ to complete via
[api]#event::wait# or [api]#event::wait_and_throw# when event _E_ is
reassociated with a new command (e.g. via [api]#khr::enqueue_signal_event# or
[api]#khr::property::signal_event#), the behavior of the [api]#event::wait# or
[api]#event::wait_and_throw# call is undefined.

An event created with the default [api]#event# constructor is equivalent to an
event created with [code]#khr::make_event# using the default platform's default
context.

=== Event properties

This extension defines no event properties.
The [code]#props# above is added for extensibility.

_Effects:_ Enqueues a command barrier.

The barrier completes when:

* All commands previously submitted to this queue have completed; and
* All events (specified by [api]#khr::property::wait_event# or
  [api]#khr::property::wait_events#) in [code]#props# have completed.

If [code]#props# contains [api]#khr::property::signal_event#, the event is
signaled when the barrier completes.

{note}If a barrier is submitted to an in-order queue with no properties, then
this operation may be a no-op.
{endnote}

== Properties

=== Applying properties to a command

Several of the functions below specify their effects in terms of a
[code]#handler# [code]#h#.
In those specifications, _applying_ [code]#props# to [code]#h# means:

* If [code]#props# contains [code]#property::signal_event#, registering the
  event that property holds to be signaled once the command is complete;
* If [code]#props# contains [code]#property::wait_event# or
  [code]#property::wait_events#, calling [code]#h.depends_on# with the event or
  events that property holds; and
* If [code]#props# contains [code]#property::use_kernel_bundle#, calling
  [code]#h.use_kernel_bundle# with the kernel bundle that property holds.

{note}No [code]#event# object is created for the command unless [code]#props#
contains [code]#property::signal_event#.{endnote}

Remember to say something about [code]#signal_event# throwing if the contexts
don't match.
